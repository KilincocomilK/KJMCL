# 游戏文件夹索引（0.7.0）

“游戏实例”页先选择游戏文件夹，再显示其中的版本。KJMCL 创建的受管实例集中在独立分组；外部文件夹保存绝对真实路径、显示名和版本索引。添加、刷新、移除索引不会复制客户端、libraries、assets、mods、saves，也不会向原目录写入所有权标记。

## 运行位置

- 共享目录：游戏工作目录和 `--gameDir` 都指向所选游戏文件夹。
- 版本独立目录：工作目录指向 `versions/<版本>`。
- 自动识别：优先读取 HMCL 的 `hmclversion.cfg` 或 `.hmcl/config/instance-game-settings.json` 中的本地运行目录配置；整合包标记和版本目录内的 mods / saves / config / options.txt 也可识别隔离。没有明确隔离信息时使用共享目录。
- 添加窗口逐版本展示实际运行路径，并允许选择共享或版本隔离。未读取其他启动器的全局配置时，请以预览路径为准，可手动选择。识别结果之后发生变化，刷新会报出冲突并保留已接受路径；在实例设置中重新识别或指定布局后才能恢复正常状态。

启动时重新读取原版本 JSON，解析继承及 `jar` 引用；classpath 中的客户端和运行库、assets 参数均指向原文件。原生库仅解压到 KJMCL 的可重建缓存，不复制原游戏目录；日志和游戏自身写入仍发生在原工作目录。核心文件缺失时明确提示在原启动器补齐并刷新，不把外部目录转换成受管实例。

外部实例支持既有资源管理、存档编辑与显式备份、参数设置、性能诊断等功能。备份和导出由玩家单独触发。克隆、搬移和受管安装入口对外部实例关闭。一个文件夹内的版本，以及运行目录互相重叠的实例，不能在运行或写任务期间并发修改。

## 生命周期与安全

添加通过主进程目录选择及有时效的预览票据完成，渲染进程不能伪造源路径。拒绝路径遍历、继承循环、嵌套文件夹、启动器数据目录重叠和运行路径被替换成链接。重复添加不会产生重复版本，刷新保留稳定 ID、备注、收藏和启动设置。

磁盘断开、版本配置被删除时保留原索引并标记不可用；重新连接并刷新后恢复。删除外部版本或整个文件夹只解除索引，原游戏与存档保留。卸载和启动器数据迁移也不会遍历外部索引路径。磁盘统计按外部文件夹计算，避免各共享版本重复计数。

状态升级到 v5，首次升级保存 `state.json.v4.bak`，保留原账户、收藏、设置和既有实例。0.6 及更早的复制导入实例仍是受管副本，无法可靠推断原路径，因此不自动转换或删除。

## 验证与参考

`tests/game-folders.test.ts` 检查原文件树不变、继承、路径替换、断盘恢复、状态迁移、去重及布局确认。`scripts/folders-desktop-smoke.mjs` 通过真实 Electron/preload 和临时 Java 程序验证原地启动、classpath、assets、共享/隔离存档、重开持久化、移除保留，以及全部导航视图。它不是实际 Minecraft、在线认证或下载源验收。

交互及目录概念参考用户提供的 HMCL 截图，以及 HMCL 的 [游戏文件夹配置](https://github.com/HMCL-dev/HMCL/blob/main/HMCL/src/main/java/org/jackhuang/hmcl/setting/GameDirectory.java)、[运行目录选择](https://github.com/HMCL-dev/HMCL/blob/main/HMCL/src/main/java/org/jackhuang/hmcl/game/HMCLGameRepository.java)。KJMCL 使用自己的 TypeScript 实现，未复制参考项目实现代码。
