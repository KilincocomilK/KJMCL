# 0.5.0 Rust 存档管理

2026-11-12。存档索引、NBT 解码、地形绘制、区块清理、属性编辑和编辑恢复由独立 Rust 程序实现。Electron 主进程负责实例边界、任务和系统对话框；React 只显示结果并提交受校验的命令。原有完整 ZIP 备份与恢复继续使用流式 TypeScript 服务。

## 使用

1. 打开“存档管理”，选择实例和存档。存档来自该实例的 `saves/`，支持名称搜索，按最后游玩时间排序。
2. 选择维度，点击区域总览或输入 **区域坐标** 跳转（一个区域为 32 × 32 区块，即 512 × 512 方块）。出生点按钮跳到主世界出生区域。
3. 地图可缩放和滚动；单击查看区块详情，拖动矩形选择，按 Ctrl 追加选择。网格、停留时间热图可切换。
4. 输入最大停留分钟或最后保存日期，选择符合条件的区块。停留时间是 Minecraft 的 `InhabitedTime`，并非建筑价值判断；最后保存日期来自 MCA 区块时间戳。
5. “预览清理”显示实际数量、相关文件数、预计减少的区域文件体积及跳过原因，再由系统对话框确认。清理后区块会在下次进入游戏时重新生成。
6. “属性”可改名称、游戏模式、难度、允许作弊、极限模式、出生点。种子精确显示为字符串；种子、游戏规则及其他未知 NBT 字段保持原值。
7. “编辑历史”提供撤销；未完成的事务提供恢复入口。也可创建完整备份、导出 ZIP 或打开目录。完整备份在原“存档备份”页恢复为新世界。

## 功能与边界

| 项目 | 当前实现 |
| --- | --- |
| 世界格式 | Java 版 `level.dat`、Anvil `.mca`；不支持基岩版 LevelDB |
| 维度 | 主世界、下界、末地，及 `dimensions/<namespace>/...` 自定义维度 |
| 区域总览 | 并行读取 8 KiB 头部，统计区块、区域文件体积和损坏信息；不预先解压整个世界 |
| 地表预览 | Java 1.13+ palette 区段；支持跨 long 位序列及 1.16+ 对齐位序列、负高度；每区块 16 × 16 像素 |
| 压缩 | gzip、zlib、无压缩、带校验的 Java LZ4Block；外部 `.mcc` 区块可读取 |
| 显示效果 | 按最高非空气方块着色的俯视预览，非游戏材质渲染；下界显示顶层，不提供洞穴切片；未知方块使用默认颜色 |
| 区块详情 | 坐标、状态、数据版本、时间戳、停留时间、压缩体积、方块实体及区段 palette 摘要；长列表有上限 |
| 清理 | 当前区域内选择最多 1,024 个区块；流式压紧 terrain / entities / poi 三类 MCA，不重编码保留区块；保留外部 `.mcc` 文件 |
| 保护 | 默认出生点半径 8 区块，可设 0–128；含末地折跃门的区块始终跳过；不能解析或不满足过滤条件的区块跳过 |
| 属性 | 仅写用户改变的字段，保留未知 NBT，包括模组附加数据；不修改种子、背包、方块、实体或游戏规则 |
| 历史 | 受影响文件完整备份、SHA-256、撤销、未完成事务恢复；不自动清理历史 |
| ZIP | 复用现有流式 ZIP / ZIP64，64 GiB / 20 万文件限制，不覆盖同名导出文件；需要先关闭游戏以取得一致副本 |

尚未实现跨区域批量编辑、区块复制粘贴、结构/原理图导出、背包与玩家数据编辑、任意 NBT 编辑、3D 视图或 MCA Selector 的完整筛选语言。旧版非 palette 地形不能生成地表预览，会明确报告错误。模组世界只提供通用格式支持，不能保证模组自定义内容的完整语义。

## 数据保护

- 所有命令绑定受管实例和存档；拒绝路径越界、符号链接与联接。renderer 不接收原生文件操作接口。
- 编辑获取 `session.lock`：Windows 使用系统文件锁；Linux 使用与 Java `FileChannel` 相容的 POSIX 锁并补充 `flock`；macOS 只使用与 POSIX 锁互通的 `flock`，避免两种锁与自身冲突。正在被外部游戏锁定时拒绝编辑；浏览为尽力读取，运行中的游戏可能让索引发生变化。
- 预览只返回有时限的一次性令牌。执行重新核对 `level.dat` 和待改文件的 SHA-256，避免预览后世界变化仍按旧计划删除。
- 先生成备份和替换文件，再持久化 prepared 日志，然后逐文件替换，最后标记 committed。多文件替换并非一次文件系统原子事务；中断后通过 prepared 日志恢复，不把部分完成当作成功。
- 撤销核对当前文件仍等于事务前或事务后摘要；有后续游戏修改时拒绝覆盖。恢复也核对备份摘要。出现未完成事务时先恢复，再进行新编辑。
- `.kjmcl-history/<uuid>/journal.json` 为 schemaVersion 1；各文件保存 `.before` 副本。备份会占用磁盘空间，因此区域压紧的预计减少量不代表整份世界立即净减少相同体积。
- `state.json` 继续为 schemaVersion 3；没有重置或迁移现有用户状态。地图缓存 `cache/save-manager-v1/` 为独立格式 1，可重建，不作为编辑依据。

## 性能设计

- Rayon 并行处理区域头和单区域区块，线程上限 8；Electron 同时最多运行 2 个 Rust 请求。不存在随整个世界大小增长的全量 NBT 解压。
- 单次地图只解码一个区域。压缩数据和解码后 NBT 均有边界限制；压紧和恢复使用流式文件读写，不将整个 MCA 留在内存。
- 地图缓存按路径、文件长度和纳秒修改时间失效，最多约 128 个区域，超限回收较旧条目。存在外部 `.mcc` 的目录跳过此缓存，避免只检查 MCA 时间导致陈旧图像。
- Rust 使用 release 构建、thin LTO；可执行文件随应用打包，启动前核对架构及 SHA-256。打包钩子拒绝把主机二进制放进其他平台或架构的应用。

### 可复现合成基准

命令：`npm run build` 后运行 `npm run benchmark:saves`。脚本只在临时目录创建和清理自己的合成世界。

Windows x64，Intel i5-12600KF，16 个逻辑处理器；128 个区域、131,072 个区块，区域文件共 537,919,488 字节。5 次扫描的范围如下，原始记录见 [SAVE-BENCHMARK.json](SAVE-BENCHMARK.json)。

| 操作 | 包含进程启动的耗时 | Rust 内部耗时 |
| --- | --- | --- |
| 整个世界区域索引 | 34.0–37.4 ms | 17.7–18.8 ms |
| 单区域首次地表预览 | 55.6 ms | 35.7 ms |
| 同一区域缓存命中 | 22.4 ms | 2.8 ms |

这是 zlib 压缩、简单单 palette 区段的合成数据，未清除操作系统文件缓存。全世界索引只读头部，不能与完整地图生成时间混用；缓存命中亦不代表首次读取速度。这些结果不证明真实大型/复杂模组存档的耗时，也未与参考项目做同条件比较。尚未测量峰值内存、低速磁盘或多用户并发。

## 验证与构建

本机已通过 `npm run typecheck`、90 项 JS 测试、12 项 Rust 测试和 `npm run test:desktop`；后者包含原有桌面与资源回归及新增存档桌面流程，使用隔离临时数据。

Rust 测试覆盖 NBT 未知字段和大整数、负坐标、地图像素和缓存、过滤与出生点/折跃门保护、terrain/entities/poi 同步清理、逐字节撤销、过期预览、后续文件变化拒绝覆盖、未完成日志恢复、越界及重叠扇区、外部区块和 LZ4 校验。桌面测试实际调用 Rust 程序，验证画布、属性保存/撤销、预览/清理/撤销和命名 IPC 路径校验，并用真实 Java `FileChannel` 持锁验证互斥；清理确认由测试提供响应。

Windows 构建含 NSIS 安装包、便携 EXE 和展开目录，未签名、未公开发布。展开目录中的 `KJMCL.exe` 另行运行了完整新增存档桌面测试，通过包内 Rust 程序执行上述读写和 Java 锁检查。macOS / Linux 仅更新了对应平台的构建和 CI 配置，尚未实际运行；没有真实 Minecraft 世界或大型模组存档的端到端验收，也没有进行系统级安装/卸载验收。合成地图和 JVM 锁测试不能替代这些验收。

本机构建命令为 `npm run build`，随后 `npx electron-builder --win --x64 --config.electronDist=node_modules/electron/dist --publish never`。本机 GitHub 下载连接未成功建立，因此打包复用了项目已经安装的同版本 Electron 45.3.0；没有替换为其他运行时版本。

开发入口：`electron/native/save-manager/src/`（Rust）、`electron/core/save-manager.ts`（进程与实例边界）、`electron/save-features.ts`（主进程操作）、`src/pages/Saves.tsx`（界面）。开发机需要 Rust stable / Cargo 与平台链接器，玩家无需另装 Rust。新增 Rust 依赖及许可证纳入 `THIRD_PARTY_NOTICES.txt`。
