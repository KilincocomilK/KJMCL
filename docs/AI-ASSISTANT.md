# AI 助手与本机 MCP

## 在启动器内使用

1. 打开侧栏 **AI 助手 → 模型服务**。选择深度求索、OpenAI、OpenRouter、Ollama、LM Studio，或添加自己的兼容服务。
2. 保存 API 基础地址和所需密钥。**检测**读取服务端的模型目录。**同步模型**更新目录，**＋**可手动添加模型 ID。点击模型设为新对话的默认值。
3. 在 **对话** 中选择模型和实例。试着输入「把这个实例的窗口调成 1600 × 900」。助手给出旧值、新值和目标实例，点击 **应用修改** 即可生效。修改记录支持撤销。启动器范围可调整下载并发、下载源和新实例默认内存等设置。
4. **诊断与维护 → 性能诊断 → 启动记录 → 询问助手** 会为当前实例准备一条消息，由玩家发送。**普通对话**适用于问答和仅支持文本生成的模型。

模型服务使用 Chat Completions 兼容接口。在线地址使用 HTTPS，回环地址支持本机 HTTP。接口路径相对于所填基础地址追加。服务端需要版本前缀时，将前缀包含在基础地址中。检测成功表示模型目录可读，具体模型的生成和工具能力由该服务提供。[DeepSeek 接口](https://api-docs.deepseek.com/api/create-chat-completion/) · [Ollama 兼容接口](https://docs.ollama.com/api/openai-compatibility)

## 从其他 Agent 连接

打开 **AI 助手 → MCP 接入**，选择端口并启用本机服务。在支持 Streamable HTTP 的客户端中导入 **复制连接配置** 的内容。采用独立字段的客户端可填写面板中的服务地址，再用 **复制令牌** 设置 HTTP 请求头。连接配置内含访问令牌。

| 客户端字段 | 值 |
| --- | --- |
| 传输 | Streamable HTTP |
| URL | 默认 http://127.0.0.1:28631/mcp，使用面板显示的实际端口 |
| Authorization | Bearer 加一个空格，再接访问令牌 |

首次启用时仅开放读取。打开 **允许提交修改** 后，外部 Agent 可生成预览，在启动器 **MCP 接入** 面板确认。Agent 可用修改 ID 查询结果。停用服务、变更权限、轮换令牌会使已有的外部待确认请求失效。已启用的服务随启动器恢复，端口被占用时可在面板更换。

KJMCL 使用官方 TypeScript SDK 的按请求处理器，支持当前协议的服务发现以及旧版无状态握手。公共资料中的 SJMCL 接入流程同样采用回环 HTTP 端点。本次实现的对照场景包括启动器内完成配置、外部 Agent 提交修改和玩家复核结果。[MCP HTTP 规范](https://modelcontextprotocol.io/specification/2026-07-28/basic/transports/streamable-http) · [SJMCL 公开接入说明](https://mc.sjtu.cn/sjmcl/docs/intelligence/launcher-mcp.html)

## 提示词和执行路径

| 层 | 实现与职责 |
| --- | --- |
| 身份与操作规则 | 主进程 prompts.ts 中的版本化系统指令约定中文术语、证据要求、工具权限与修改状态。MCP 向客户端公告相同的工具使用规则。 |
| 场景 | 内存调优、启动诊断、视频设置和下载配置各有取证顺序。场景入口与 MCP prompts 共用 shared/assistant-scenarios.ts。 |
| 对话范围 | 首次发送时固定服务商、基础地址、模型、模式和实例 ID。普通模式只发送对话。配置模式按需读取选定实例和启动器设置。 |
| 工具契约 | electron/core/assistant/tools.ts 注册工具名称、参数、说明和执行函数。Zod 契约同时生成模型函数定义和 MCP 工具定义。配置提交、接受和撤销各有明确的状态。 |
| 历史与反馈 | 最近的对话和配置回执参与下一轮上下文，原始协议报文与模型推理片段仅在当前请求循环中使用。工具角色单独携带结果。错误、等待确认和实际保存有各自的界面状态。 |

每次提问最多 6 轮模型请求、12 次工具调用、4 分钟。读取结果可进入下一轮推理。生成修改后，对话暂停在玩家可操作的差异卡。流式回复支持停止，截断的工具参数会被丢弃。切换服务商或端点需要开启新对话。

### 工具目录

| 工具 | 用途 |
| --- | --- |
| launcher_overview | 启动器设置、系统可用内存、分页实例清单 |
| instance_settings | 指定实例的运行参数、预计堆大小、可编辑视频字段 |
| installed_content | 分页查看实例的模组、资源包或光影 |
| launch_diagnosis | 查看最近或指定启动记录的诊断结论、Java 主版本和 GC 停顿 |
| configure_launcher | 提交默认内存、下载源、并行数、显示快照、启动前备份和启动后最小化的差异 |
| configure_instance | 提交内存策略及上限、垃圾收集器、GC 日志、窗口尺寸和全屏差异 |
| configure_video | 提交该游戏版本已经保存的视距、模拟距离、帧率上限和实体距离倍率差异 |
| change_status | 查询本来源的修改编号及处理状态 |

主进程在确认时重新读取受影响字段，实例操作沿用目录归属检查、游戏运行检查和任务互斥。比较成功才写入。撤销同样复核字段，保留玩家在其他设置上的改动。视频修改使用原有备份机制，退出启动器后仍可从性能诊断页还原。待确认预览有效期为 15 分钟，实时审批与通用撤销面板属于本次运行。

### 数据与扩展

服务商设置保存在数据目录的 assistant/config.json，对话分别保存在 assistant/chats 下。启动器的数据迁移同时携带这些文件和 credentials 中的加密凭据。API 密钥和 MCP 令牌由操作系统安全存储管理。更换 API 地址会解除旧密钥绑定。主进程只向界面返回是否已保存密钥，复制 MCP 配置也由主进程完成。

助手配置与对话各自携带 schemaVersion。v1 升级至 v2 时备份原文件，保留原有模型和对话。同步只替换服务端目录，手动添加的模型继续保留。个别对话损坏时，历史面板标明受影响的文件，其余对话和管理面板仍可使用。

新增工具时在注册表中声明严格参数和权限，选择对应领域服务，给读取、预览、旧值冲突和撤销补充测试。扩展 IPC 时同步更新 shared/assistant.ts、shared/schema.ts、electron/preload.ts 与主进程处理器。模型密钥、网络请求、文件操作和服务监听均由 Electron 主进程持有。

| 7 | 将助手请求的取消和设置写入接入启动器原有退出流程。桌面回归覆盖关闭后重启、对话与修改回执恢复、凭据脱敏，以及从诊断页带入实例。 |

本次 Windows x64 预览在 JDK 21.0.7 环境通过类型检查、377 项单元测试、生产构建和完整桌面回归。打包后的 KJMCL 也通过了助手桌面用例，覆盖模型目录、凭据、配置确认与撤销、重启和紧凑布局。

单元测试使用临时目录和协议夹具。桌面助手测试通过回环 HTTP 夹具模拟模型目录与工具回复，并在 Windows 验证系统加密凭据。按此次开发范围，真实云模型、外部 Agent 客户端及非 Windows 桌面联调留待单独验收。
