# 0.6.1 自动轻量模式

日期：2026-11-12；本机验证平台为 Windows x64。

## 玩家体验

- 游戏进程成功启动并保持运行约 1.5 秒后，自动进入轻量模式；无需确认。进程立即退出或启动检查失败时不切换。
- 独立的黑橙精简窗口显示正在运行的实例，保留“结束游戏”“打开完整界面”和窗口控制。进入时弹出“已进入轻量模式，减少启动器资源占用”。
- 多开时，只有最后一个游戏进程退出才恢复完整界面，并弹出“已退出轻量模式，完整界面已恢复”。正常退出、崩溃和玩家主动结束都适用。
- 游戏运行期间可以打开完整界面；本次游戏会话内保持完整界面，底部可再次进入轻量模式。所有游戏结束后，下次启动重新自动进入。
- 保留“启动后最小化”的设置。窗口原本在后台时，切换使用不抢焦点的显示方式；原本最小化时继续保持最小化。通知在玩家查看窗口后自动消失，无确认按钮。
- 完整界面恢复后从已保存状态重新加载，显示首页。账户、实例、游戏时长和任务状态保留；未提交的页面草稿不保存。主进程正在处理的修改或原生对话框完成前不会切换。

## 资源开销

`electron/core/lightweight.ts` 根据真实进程的 spawn / close 生命周期调度，不用轮询发现游戏。启动后延迟进入，避免短暂失败时闪烁；切换串行执行，游戏在切换中结束也会随后恢复。

`electron/window-host.ts` 先载入新窗口，成功后销毁原窗口及其 webContents，释放完整 React 界面的渲染进程。轻量页面使用单独的内存 session，避免复用完整界面的渲染进程；加载失败则销毁候选窗口并恢复原窗口。恢复时保留完整窗口的尺寸和最大化状态。

轻量页面独立构建，不加载 React、图标库、地图、资源预览或完整页面代码；无动画、无定时轮询。仅在实例列表或后台任务数量发生变化时更新，状态通知最多每秒一次。游戏逐行日志与完整状态不发送给轻量界面，防止日志刷屏导致持续渲染。

日志仍经过脱敏后写入文件，主进程保留原有最近日志与退出诊断。Java 进程、下载任务、账户流程和陶瓦进程继续运行，不改变 JVM 内存、游戏参数、系统优先级或游戏画质。轻量模式主要降低启动器界面的开销；后台下载和联机本身仍需要资源。

## 安全与状态

新增 `lightweightState` / `setLightweight` 命名 preload 方法、共享类型、Zod 输入验证及主进程处理。轻量窗口保留 context isolation、sandbox 和禁用 Node 的限制；主进程仅接受其精简状态、切换模式、结束游戏和窗口控制四类调用。恢复完整界面后才开放其他操作。

模式是本次进程内的临时状态，不写入 `state.json`，不改变 v4 数据结构。正常关闭启动器沿用原有确认流程；自动切换窗口不触发退出确认，也不会停止陶瓦或取消任务。

## 验证方法

`tests/lightweight.test.ts` 覆盖自动进入、最后一个进程退出、立即退出、手动恢复、等待修改完成、切换期间退出、加载失败重试、退出取消及 IPC 类型约束。

`scripts/lightweight-desktop-smoke.mjs` 使用一次性数据目录与真实 JVM 子进程夹具，检查旧 renderer PID 从 Electron 进程列表中消失、仅剩一个窗口、轻量页面没有 React 根节点或逐行日志事件，并验证双实例、正常 / 异常退出、启动失败、界面加载失败恢复、最小化通知、主进程日志与脱敏。测试不下载 Minecraft，也不连接真实账户或房间。

脚本还记录 3 秒资源采样：JVM 每秒输出约 100 行日志，对比完整日志页面与精简页面。使用 Electron `app.getAppMetrics()`，不包含 JVM 内存；Windows 私有内存为启动器各进程 privateBytes 合计，CPU 为 Electron 报告值合计。结果会随硬件、日志量、页面和后台任务而变化，不是 Minecraft 帧率基准。

本机最终源码构建的采样如下，原始记录见 [Windows 采样数据](lightweight-win32-sample.json)：

| 指标 | 完整日志页面 | 轻量页面 |
| --- | ---: | ---: |
| 启动器私有内存合计 | 378.17 MiB | 325.48 MiB |
| 界面进程私有内存 | 66.78 MiB | 32.47 MiB |
| 启动器 CPU 采样合计 | 2.08% | 0.27% |

这是一次短时合成测试样本，不是固定节省比例；用于确认释放界面和停止日志渲染确实降低了该负载下的开销。

`npm run typecheck`、`npm test`（112 项）、`npm run test:native`（12 项）及完整 `npm run test:desktop` 均已通过。桌面套件同时回归原有启动、资源拖入、Rust 存档、内容与实例管理流程。轻量专项还验证了取消原生退出确认后继续自动恢复、最小化超过通知显示时长仍保留提示。

最终 Windows 解包程序再次通过轻量专项测试。11 个完整 / 轻量界面、主进程、preload 和 sourcemap 文件，以及第三方声明、版本号、Rust 组件，均已与受测构建核对一致。Windows 构建使用 `npm run build` 和 `npx electron-builder --win --x64 --config.electronDist=node_modules/electron/dist --publish never`，产物位于 `release/0.6.1/`；安装包和便携包的摘要见同目录 `SHA256SUMS.txt`。没有执行系统级安装或发布。

本轮还修正了回归测试发现的视频预设按钮竞争：应用或还原完成前禁用再次操作，避免“应用后立即还原”被实例任务锁拒绝。
