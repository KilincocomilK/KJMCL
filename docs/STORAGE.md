# 数据目录与卸载策略（0.3.1）

把数据统一放进程序安装目录并不是可靠默认值：Program Files 等位置可能不可写，macOS 应用包与 Linux 系统安装目录也不适合游戏写入；Windows 标准卸载/升级会清理安装目录。KJMCL 区分稳定控制目录、可迁移数据目录和玩家单独指定的外部 MC 目录。

## 目录选择

| 模式 | 初始位置 | 行为 |
| --- | --- | --- |
| 新安装 | 平台用户目录中的 KJMCL/data | 首次显示目录选择，可直接选择 D/E 等盘上的独立空目录 |
| 从旧版升级 | 原数据目录 | 不暗中移动、不创建空配置替代原数据 |
| Windows 便携 | 外层 EXE 旁的 KJMCL-data | 使用 PORTABLE_EXECUTABLE_DIR，不使用 NSIS 临时解压目录 |
| KJMCL_DATA_DIR | 指定隔离控制目录，首次也作为数据目录 | 用于测试/高级隔离；之后可按该目录内的位置记录找到迁移数据 |

安装版的数据目录独立于安装目录。用户把程序安装在 D 盘时，可以选择例如 `D:/Games/KJMCL-data`；不建议把数据放进会被卸载器清除的程序文件夹。改变“默认实例根目录”仅影响新实例；“迁移数据”则包含公共资源、托管 Java、备份和已在数据根内的实例。

Electron 的 `userData/sessionData` 保持在控制目录，避免改变 `Local State` 等加密配置位置。实际 Windows 测试确认只搬密文并改变 Chromium 配置位置会导致解密失败，因此本实现不这样处理。占空间的游戏数据、资源、Java、下载缓存及备份放到用户选定磁盘；界面 HTTP 磁盘缓存设置 32 MiB 上限，GPU/其他 Chromium 元数据并不包含在这个上限中。[Electron 路径接口](https://www.electronjs.org/docs/latest/api/app/)、[safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage)、[缓存大小选项](https://www.electronjs.org/docs/latest/api/command-line-switches)。

## 迁移事务

1. 只有游戏和任务已停止，且没有其他进行中的 API 操作，才能迁移。迁移期间及等待重启期间暂停新的写入。
2. 目标必须为空、为规范化绝对子目录，不得与源数据、程序或任一实例目录重叠。拒绝磁盘根目录、符号链接和目录联接；检查目标空间。
3. 只枚举 KJMCL 管理的目录与状态文件，不复制未知个人文件或跟随 state.json 中的外部实例路径。逐文件复制并验证 SHA-256，再检查源文件没有变化。
4. 重写活动状态中的内部实例、Java 和默认实例目录路径，保留外部路径。保存迁移记录后原子切换位置记录，原文件保留。
5. 重启从新目录加载。记录包含路径切换完成前中断的情况，可以验证已复制目标并继续切换。若迁移在复制阶段被进程强制结束，可能留下未完成目标目录；原数据仍保留，需要检查或改用新的空目标。
6. “清理原数据”单独显示原位置，并再次验证仍存在的原文件摘要。文件后来被修改或新增时拒绝清理；已完成部分清理后中断可继续。仅删除记录内文件、空目录及原数据位置的旧应用日志目录，不删除整个控制目录。

`storage-location.json` 使用独立版本 1；游戏 `state.json` 仍为 v3。数据归属标记记录随机 owner，与控制记录一致才允许清理。历史 `.bak` 保留原内容以便手动恢复；自定义 JVM 参数或模组配置中手写的绝对路径不作猜测式替换，迁移后需自行检查。

## 卸载

Windows NSIS 在交互式、非升级卸载时调用应用的数据审阅入口，在删除程序文件前询问：

- **保留数据并卸载**：默认选项；不清理受管数据。
- **删除数据并卸载**：永久清理展示的当前用户数据根及未清理迁移副本中的受管内容，包括其中的世界和备份。外部自定义 MC 目录和未知文件保留；请先关闭所有游戏。
- **取消卸载**：退出卸载流程，保留程序。

清理先校验全部根目录的归属及其内部链接，再执行删除；不会按状态文件中的任意 gameDir 递归删除。若数据与程序目录重叠，取消卸载并要求先迁移，避免“保留数据”后仍被程序卸载流程删除。清理发生 I/O 错误时可能已删除部分用户选择删除的受管文件，错误会阻止继续卸载；这不是可回滚删除。

升级与普通静默卸载保留数据。`--delete-app-data` 会明确拒绝，避免 electron-builder 内置的宽泛 profile 删除逻辑绕过此策略。控制目录的少量定位/加密配置及未知文件不会被整个递归删除，便于重装重新连接数据位置。[electron-builder NSIS 扩展接口](https://www.electron.build/v26/docs/nsis/)。

macOS 删除 `.app`、Linux 包管理器卸载以及删除便携 EXE 都不会触发此 Windows 对话框，数据默认保留。没有实现跨平台系统卸载 UI 钩子。

便携版迁移后的重启调用外层 `PORTABLE_EXECUTABLE_FILE`，而非临时解压的内部 EXE。当前固定的 electron-builder 26.18.0 中，`NsisTarget.js` 只有在 `unpackDirName` 为真值布尔量时才不定义固定 `UNPACK_DIR_NAME`，因而配置为 `true`，使用每次启动独立的 `$PLUGINSDIR/app`。这与该版本类型注释所写的 `false` 不一致；升级构建器时必须复核生成脚本，避免新旧便携进程的解压目录清理相互影响。

## 验证边界

核心测试覆盖默认/旧版/便携路径、便携文件夹重定位、跨目录复制与校验、取消、路径切换中断、原数据变化、部分清理重试、符号链接/联接、归属错误、程序目录重叠，以及保留/删除/取消三个业务分支。

`scripts/storage-smoke.mjs` 在 Windows 实际 C: → F: 临时目录中运行 Electron，验证迁移、重开、内部路径、外部 MC 目录、实际 safeStorage 密文可解密和显式清理。首次目录选择也经过真实 renderer/preload/IPC 检查。对话框测试提供临时路径/明确的测试选择，未处理真实玩家数据。

`scripts/uninstall-smoke.mjs` 运行实际 Electron 主进程卸载入口，由测试提供三种对话框响应，检查退出码、默认保留选项以及受管/外部/未知文件的清理边界。

`scripts/portable-storage-smoke.mjs` 使用 `KJMCL_PORTABLE` 指定的真实便携 EXE，在独立临时文件夹中运行。已验证旁置数据、迁移后的外层程序重启、新 PID、旧包装进程清理完成后重新加载界面，避免仅测试内部 EXE。测试仅在执行时启用本机调试端口；正常启动不启用。

Windows 安装器需要实际编译通过；安装包内应用另跑桌面与存储回归。这里不将业务分支测试或安装器编译称为在用户系统上真实安装/卸载验收，也不声称 macOS/Linux 已实测。
