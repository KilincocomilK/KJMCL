# KJMCL

Minecraft Java 版桌面启动器，开发版 **0.7.2**。Electron + React + TypeScript，存档引擎使用 Rust，面向 Windows、macOS 和 Linux。

作者：[KilincocomilK](https://github.com/KilincocomilK)。项目仓库：[KilincocomilK/KJMCL](https://github.com/KilincocomilK/KJMCL)，目前保持私有。

继续开发前先读 [本轮开发交接](docs/HANDOFF.md)，其中包含当前验证范围、本机清理后的实际数据位置及下一阶段建议。

独立实现，未复制 HMCL / SJMCL 的代码。0.3.0 对照了两者最新公开仓库的功能与配置，详见 [高级功能差距与路线](docs/LAUNCHER-COMPARISON.md)。本地参考目录不参与构建。界面参考 [KJMC 官网](https://kjmc.top) 的橙色 `#f26b21`、直角、细线边框与暗色表面；图标、几何风景为本项目原创。

## 开发

开发工具链固定为 Node.js 24.22.2（见 `.node-version`）、npm 11.19.1（见 `packageManager`），另需 Rust stable / Cargo 及系统原生链接工具（Windows 使用 MSVC 构建工具）；运行游戏另需相应版本 Java。桌面集成测试需要 PATH 中有 JDK 17 或更新版本。Rust 核心随应用打包，玩家无需安装 Rust。

```sh
npm ci
npm run dev
```

```sh
npm run typecheck
npm test
npm run test:native
npm run test:desktop
npm run test:storage
npm run test:uninstall
npm run test:installer
npm run build
npm run pack      # 当前平台的应用目录
npm run dist      # 当前平台的安装包，输出到 release/<版本>/
```

`npm run preview` 仅供浏览器布局预览，不具备文件系统或启动能力，不提供伪造的账户和实例数据。桌面开发模式下修改主进程后需要重启 `npm run dev`。

## 使用

1. 点击左下角账户入口，添加离线账户，或配置 Microsoft Client ID 后登录。
2. 新建游戏实例，或在“游戏实例 → 添加游戏文件夹”选择已有 `.minecraft`。确认各版本的运行位置后添加；游戏文件和存档保持原位，不复制到启动器目录。
3. 在“设置”检测 Java；必要时安装游戏要求的版本。实例设置可覆盖全局 Java。
4. 在“资源管理”选择实例，直接搜索和安装模组，或切换光影、资源包、录像、原理图分类。CurseForge 需要在设置中保存 API Key。
5. 在“启动器设置 → 外观”选择本地背景图片，调节暗度和模糊；恢复默认可移除自定义背景。
6. 返回首页选择版本并启动。“存档管理”集中提供世界编辑与备份；“诊断与维护”集中提供性能、日志、崩溃报告及磁盘管理。

外部文件夹可刷新版本、调整运行位置识别方式、移除索引；移除索引不删除游戏。外部版本的核心安装和修复仍由原启动器负责。旧版已经复制的实例会继续保留，不会自动删除或切回原目录。详细行为见 [游戏文件夹索引](docs/GAME-FOLDERS.md)。

如需代理，在设置中输入 `http://127.0.0.1:7890` 并保存。默认不强制依赖本地代理。Java 路径应指向 `java` / `java.exe`，不要选择目录或 `javaw.exe`（需要保留控制台输出）。

Microsoft 登录需要项目自己的应用注册 Client ID，启用个人 Microsoft 账户和公共客户端设备码流，并满足 Minecraft 服务对第三方应用的准入要求。项目不借用其他启动器的应用 ID。Client ID 是公开配置，不是 client secret；不要把 secret 填入界面。Linux 需要可用的系统密钥服务，拒绝明文后备存储。

## 数据

安装版使用稳定的控制目录（Windows 通常为 `%APPDATA%/KJMCL`，macOS 为 `~/Library/Application Support/KJMCL`，Linux 为 `~/.config/KJMCL`）保存数据位置及 Electron 的加密配置。全新安装的数据默认放在其 `data/` 子目录，首次打开可选择其他磁盘；升级用户保持原目录。Windows 便携版默认使用外层 EXE 旁的 `KJMCL-data/`，与安装版是独立的数据环境。界面“设置 → 数据目录”显示实际位置。

游戏、共享资源、托管 Java、下载缓存、备份和加密凭据可以整体迁移。控制目录及少量界面缓存保留原位，避免账户凭据因加密配置变化而失效；界面 HTTP 磁盘缓存上限设为 32 MiB。目录策略、迁移和卸载说明见 [STORAGE.md](docs/STORAGE.md)。

```text
state.json             # schemaVersion=6，账户、实例、游戏文件夹索引、设置、收藏与外观
state.json.bak         # 上次保存的状态
state.json.v1.bak      # 首次从 0.1 升级时保存的原始状态
state.json.v2.bak      # 首次从 0.2 升级时保存的原始状态
state.json.v3.bak      # 首次升级 0.6 时保留的旧状态（实例与账户不重置）
state.json.v4.bak      # 首次升级 0.7 时保留的旧状态（不改变旧实例路径）
state.json.v5.bak      # 首次从 v5 升级 0.7.2 时保留的原始状态
appearance/<uuid>.png  # 已导入的背景副本，删除源图片不影响使用
diagnostics/<uuid>.json # 最近 12 次启动记录，不保存完整带令牌命令
video-backups/<uuid>.json # 可还原的视频设置字段
credentials/           # 系统加密的 Microsoft 刷新令牌与 .vault 凭据，不发给界面
instances/<uuid>/      # 默认游戏目录；也可由 gameDir 指向任意磁盘上的独立空目录
backups/<uuid>/        # 存档 ZIP 与校验元数据
libraries/             # 共享运行库
assets/                # 共享游戏资源
runtimes/              # 托管 Java
cache/                 # 元数据和临时下载
```

控制目录另有 `storage-location.json`（独立版本 1），记录活动数据位置；`.kjmcl-data.json` 是数据目录归属标记。迁移中的 `storage-migration.json` 记录逐文件校验结果，不包含凭据明文。

完整备份启动器数据时先关闭应用，并另外备份自定义游戏目录。首次升级自动迁移 v1–v5 状态，保留账户、原实例位置和手动内存；不要用旧版程序打开已升级数据。测试或隔离运行可设置 `KJMCL_DATA_DIR` 为专用绝对路径，不影响默认用户数据。

## 0.7.2 界面与自定义背景

左侧导航与主面板分别悬浮在背景上，使用深色毛玻璃和细线边框保持区分度。首页集中保留实例选择和启动操作，移除重复卡片、内存统计及“就绪”“JAVA EDITION”等装饰文字。页面与弹窗使用统一下拉菜单，支持方向键、Home / End、输入匹配、Enter 和 Escape。

“启动器设置 → 外观”支持 PNG / JPEG 图片、背景暗度、模糊及恢复默认。图片由主进程校验并复制到受管数据目录，源图移动或删除后仍可使用；过大的图片会缩放，文件上限为 20 MiB。外观随启动器数据迁移，状态升级至 schema v6，保留账户、实例、外部游戏文件夹和旧状态备份。

发布说明见 [0.7.2](docs/releases/0.7.2.md)，实际验证范围见 [验证记录](docs/VALIDATION.md)。

## 0.5.0 Rust 存档管理

在“存档管理”选择实例和世界，查看主世界、下界、末地及自定义维度。点击区域总览或输入区域坐标打开地表地图，支持缩放、框选、区块详情、停留时间和最后保存日期过滤。清理会同步处理地形、实体、POI，默认保护出生点附近区块，并保护末地折跃门；先预览，再备份并执行。

世界属性可编辑名称、游戏模式、难度、作弊开关、极限模式及出生点。每次编辑生成带 SHA-256 的恢复记录，支持撤销与中断恢复；之后被游戏修改的文件不会被撤销操作覆盖。完整功能、Rust 架构、兼容范围、合成基准和验证边界见 [存档管理说明](docs/SAVE-MANAGER.md)。

构建自动生成当前平台的 Rust 可执行文件，打包时校验平台与架构；macOS / Linux 包需在对应系统构建。`npm run benchmark:saves` 可复现合成存档索引与单区域地图基准。

## 0.3.1 目录与卸载

- 设置中选择“迁移数据”，目标必须为空且不能与程序/实例目录重叠。逐文件复制和 SHA-256 校验后，重启切换；确认新目录正常后点击“清理原数据”释放原磁盘空间。外部自定义 MC 目录不会移动。
- Windows 交互式卸载提供保留、永久删除受管数据、取消三种选择，默认保留。升级及普通静默卸载保留数据，不接受绕过交互保护的 `--delete-app-data` 参数。
- 卸载的数据清理范围包括活动目录及尚未清理的迁移副本中的受管文件；外部 MC 目录、未知文件、控制目录定位信息及系统加密配置保留。不存在“递归删掉任意自定义目录”的逻辑。
- 便携版没有卸载器；删除 EXE 不删除旁边的数据目录。把便携文件夹整体搬到同一系统后，会修正内部实例/Java 路径；跨电脑的加密凭据仍可能需要重新登录。安装版旧数据不自动导入便携环境。

## 0.3.0 性能与诊断

选择侧栏“性能与诊断”，为实例保存内存、Java 和 GC 配置，再执行“检查并试运行 JVM”。自动模式不超过用户设置的内存上限，启动时重新计算；默认 GC 跟随 JVM。试运行不登录账户或加载游戏、模组和自定义代理，也不验证全部自定义参数。

启用 GC 记录后，下次退出会生成停顿摘要，最近 12 次启动记录重开后仍可查看和导出。日志不等于 FPS 测量；尚无世界内性能提升的对照结论。游戏视频预设需先运行游戏生成 `options.txt`；只改已有的四个性能字段，可还原。预设字段后来在游戏中修改时会拒绝覆盖，保留玩家修改。

自动/手动、G1/ZGC 等均为可选设置，不会替既有实例自动安装性能模组或改变原始存档。完整比较、剩余差距及分阶段验收条件见 [调研报告](docs/LAUNCHER-COMPARISON.md)。

## 0.2.1 启动修复

- 启动前检查并按元数据校验、补齐 Log4j 配置，修复导入实例只有少量日志和 Reconfiguration failed 的问题；无需重新导入。首次补齐需要联网。
- 导入时从客户端 JAR 的 `version.json` 读取真实 Minecraft 版本，避免把重命名的配置 ID 当作基础版本。旧导入实例会在首次启动时自动纠正。
- 官方 XML 日志转换为可读消息与堆栈，保留错误级别；显式结束游戏会记录停止请求及退出原因。
- 启动位置在游戏运行期间不再变成结束按钮；结束游戏使用独立按钮，避免连续点击启动位置误杀刚启动的进程。

## 新功能使用约定

- 新建、克隆和已有目录导入均可指定游戏目录；设置中的“默认实例目录”仅影响之后创建的实例。新目录必须为空，不能覆盖启动器数据或与现有实例重叠。实例设置“更换目录”执行复制迁移，保留原文件。所有权标记用于防止误删不属于实例的目录。
- “导入目录”选择包含 `versions/<版本>/<版本>.json` 的 `.minecraft` 根目录，选择版本后复制到新实例；支持继承、中文版本名和常见版本隔离目录。源目录必须已有完整客户端和运行库，原目录不做修改。Forge / NeoForge 与导入实例在 `.kjmcl-runtime` 内使用独立运行库和资源。
- Forge / NeoForge 使用校验后的官方安装器，调用无界面 `--installClient`，支持 7890 HTTP 代理；详细输出在实例 `logs/loader-install.log`。官方安装器内部下载不受 KJMCL 镜像选择控制。旧版安装器若不支持该 CLI 会明确报错。
- 第三方账户填写完整 HTTPS Yggdrasil API 根地址。密码仅用于本次登录，认证令牌加密保存；启动时加载校验后的 authlib-injector。服务必须实现相应接口，角色切换需停止游戏。
- 存档备份需游戏停止，单次支持不超过 64 GiB、20 万文件，不包含 `session.lock`。恢复校验归档后写入新世界目录；备份保留在启动器数据目录，即使实例已删除也不自动抹除备份文件。暂不自动清理历史备份。
- 发布包仅包含当前平台可追溯、未被修改的启用模组及 `config`，生成旁置 `.manifest.txt` 文件清单。混合来源或本地 JAR 可用 KJMCL 私有格式导出，但不能直接生成公开标准包。请检查配置内容是否适合分享。
- Modrinth 发布需在设置保存有上传版本权限的令牌，目标项目须已存在且为整合包；按钮会展示最后一次系统确认。CurseForge 输出标准 ZIP 后由用户上传作者后台。没有自动创建远程项目或自动发布。

## 验证范围与开发版边界

- Windows 本机验证：构建、核心测试、实际 Electron 窗口操作、账户持久化、实例设置、模组开关、Java 检测、真实 JVM 启动测试程序与日志脱敏。
- 下载器和完整安装流程使用合成元数据与文件测试。按本轮要求，未在线验收 Minecraft、Modrinth、BMCLAPI、Fabric、Quilt、Adoptium 下载源，未执行全量真实游戏下载；0.2.1 已使用本机已有的 1.21.11 Fabric 客户端及模组的隔离副本验证到渲染 / 音频初始化，使用离线测试身份。
- Microsoft 流程已实现，尚未用项目 Client ID / 真实账户联调。
- 提供三个操作系统的构建配置与 CI；macOS / Linux 尚未在本机实测，配置不等于已完成跨平台验收。
- 新增功能通过本地数据、合成 API 和实际 JVM 安装器测试程序验证；没有使用真实第三方账户、真实官方 Forge / NeoForge 安装器、真实皮肤上传或远程发布操作。下载源仍按要求不在线验收。
- 离线皮肤仅为启动器本地预览，不注入原版游戏；第三方上传需要服务端支持 authlib-injector 皮肤扩展。
- 暂无自动升级、云备份和自动识别本地 JAR 的来源。
- 下载采用校验后复用完整文件，不支持 HTTP Range 断点续传。模组更新仅覆盖从本应用 Modrinth / CurseForge 安装并记录的文件；本地 JAR 不自动识别远程项目。
- 旧版游戏与 Apple Silicon 的原生库支持取决于上游提供的架构。没有兼容 Java / 原生库时需指定适配运行时；未实现 Rosetta 或旧 LWJGL 的自动替换。
- 关闭启动器会取消任务，正在运行的游戏继续运行；重新打开后不能重新附着旧进程日志。游戏运行期间建议保留启动器。
- 未配置平台签名、公证和自动更新渠道；Windows 构建未签名。

架构、测试规范、发布及待确认事项见 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md)、[docs/DECISIONS.md](docs/DECISIONS.md)。
